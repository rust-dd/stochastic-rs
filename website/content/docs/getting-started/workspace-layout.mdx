`stochastic-rs` is a Cargo workspace with **8 sub-crates** as siblings under the workspace root. The `stochastic-rs` umbrella crate re-exports six of them as modules — `stochastic_rs::distributions`, `stochastic`, `copulas`, `stats`, `quant`, and `ai` with the `ai` feature — and `stochastic-rs-core`'s RNG module as `stochastic_rs::simd_rng`. `stochastic-rs-py` builds the Python module and is not re-exported.

```
stochastic-rs/                        (workspace root + umbrella crate)
├── stochastic-rs-core/               simd_rng (foundation)
├── stochastic-rs-distributions/      FloatExt, SimdFloatExt, 35 SIMD distributions
├── stochastic-rs-stochastic/         ProcessExt, 132 processes
├── stochastic-rs-copulas/            BivariateExt, MultivariateExt, 23 copulas (15 + 8)
├── stochastic-rs-stats/              MLE, Hurst, realised, stationarity, …
├── stochastic-rs-quant/              ModelPricer, calibration, vol surface
├── stochastic-rs-ai/                 Experimental neural surrogates (feature-gated)
└── stochastic-rs-py/                 PyO3 module (308 classes and functions)
```

## Dependency topology

```
stochastic-rs-core (simd_rng)
          │
          ▼
stochastic-rs-distributions (FloatExt, SimdFloatExt)
          ├──────────────────────────────┐
          ▼                              ▼
stochastic-rs-stochastic        stochastic-rs-copulas
          │                              │
          ▼                              │
stochastic-rs-stats                      │
          │                              │
          ▼                              │
stochastic-rs-quant ◄────────────────────┘
          │
          ▼  (optional)
stochastic-rs-ai
```

An arrow points to a crate that depends on the one above it. Every crate also depends directly on `stochastic-rs-core`; `stochastic-rs-stats` also on `-distributions`, and `stochastic-rs-quant` on `-distributions` and `-stochastic`. `stochastic-rs-ai` reaches `-quant` through its optional `quant` feature, which the umbrella's `ai` feature turns on. The umbrella and `stochastic-rs-py` depend on all of them, `-ai` optionally.

## Why depend on a sub-crate

1. **Compile time.** Pulling only `stochastic-rs-distributions` for a distribution-sampling job avoids compiling the quant and AI surface.
2. **Feature gating.** `ai`, `cuda` and `metal` live on the crates that own the optional dependency, so a default `cargo build` never tries to link CUDA on a machine without it.

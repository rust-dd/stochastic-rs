The `stochastic_rs` Python package wraps the Rust crates via PyO3: 286 classes and 22 functions across distributions, stochastic processes, pricers, calibrators, copulas and stats (see [Python bindings](/docs/python)).

## From PyPI (pre-built wheels)

```bash
pip install stochastic-rs
```

Wheels are published for:

- **CPython** 3.11 / 3.12 / 3.13 / 3.14, and free-threaded 3.14t
- **Linux** (manylinux x86_64, aarch64), **macOS** (Apple Silicon, arm64), **Windows** (x86_64)

On any other platform `pip` builds from source, which needs a Rust toolchain.

## Build from source

You need the Rust toolchain (`rustup`), Python 3.11 or newer, and `maturin` 1.9.4 or newer.

```bash
git clone https://github.com/rust-dd/stochastic-rs.git
cd stochastic-rs

python -m venv .venv
source .venv/bin/activate

pip install "maturin>=1.9.4"
maturin develop --release
```

Run it from the workspace root; `pyproject.toml` points maturin at the Python crate. Add `--features metal`, `cuda`, `accelerate` or `ai` for the parts the published wheels leave out.

## Verify

```python
import stochastic_rs as srs
import numpy as np

p = srs.PyOu(theta=2.0, mu=0.0, sigma=1.0, n=1000, x0=0.0, t=1.0)
path = p.sample()
assert isinstance(path, np.ndarray)
assert path.shape == (1000,)
print("OK", path.mean(), path.std())
```

If this prints two finite numbers, continue with the [Quickstart](/docs/getting-started/quickstart).

## NumPy interop

Every `sample()` returns NumPy arrays. A one-dimensional process's `sample_par(m)` returns an `(m, n)` array; a distribution's `sample_par(m, n)` does too. The dtype is `float64` by default; pass `dtype="f32"` for `float32` where the class takes it (most distributions and processes do).

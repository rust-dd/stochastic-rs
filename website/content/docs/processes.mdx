The `stochastic-rs-stochastic` crate ships **129 processes** in eleven families (below). Every process implements [`ProcessExt<T>`](/docs/concepts/process-ext): `sample()` returns one path, `sample_map(m, f)` maps over `m` paths in parallel, and `sample_par(m)` returns `Vec<Output>` (one `ndarray::Array1<T>` per path for single-factor models).

## Choosing a family

| You need | Start with | Then |
|---|---|---|
| A price path with constant volatility | `Gbm` (exact log-normal steps) | `GbmLog` for the log-price, `Cev` for a local-vol elasticity |
| Mean reversion | `Ou` (Gaussian), `Cir` (positive, square-root), `Vasicek` / `HullWhite` for rates | `CirPlusPlus` to fit a term structure, `Cheyette` for a quasi-Gaussian HJM |
| Stochastic volatility | `Heston` (Euler / QE schemes), `Sabr`, `Bergomi` | `DoubleHeston`, `MultifactorHeston`, `HestonStochCorr`, `HestonSlv` |
| Rough volatility | `RoughBergomi` (hybrid scheme), `Fheston`, `RlHeston` (Markov lift) | the `volterra` module for a general kernel |
| Long memory / fractional noise | `Fgn` → `Fbm`, `Fou`, `Fcir`, `Fgbm` | all driven by the fGN FFT pipeline, on the host or a device |
| Jumps | `Merton`, `Kou`, `Bates`, `CompoundPoisson`, `Hawkes` | `LevyDiffusion` with any `Distribution` for the jump size |
| Several correlated assets | `Mcgns` (driver) → `MultiGbm`, `Wishart` (covariance) | `Cfgns` for correlated fractional noise |
| A rates curve, not a rate | `Hjm`, `Lmm`, `Adg` | `G2pp`-style two-factor: `HullWhite2F`, `Cir2F` |
| Time-series style | `Ar`, `Arima`, `Garch` / `Egarch` / `GjrGarch`, `Sarima` | the stats crate fits them |

#### Discretisation schemes

`sample()` integrates the variance with the **Euler** full-truncation scheme by default. For large `κ`, high `|ρ|` or long maturities Euler carries a noticeable discretisation bias; switch to the Andersen (2008) **Quadratic-Exponential (QE)** scheme with `.qe()`:

<RustExample path="tests/doctest_processes_heston_qe.rs" />

The scheme is a zero-sized type parameter (`Heston<T, Sch, S, B>`), so the choice costs no per-step branch. QE is defined for the square-root (CIR) variance only, so keep `HestonPow::Sqrt`. Reference: Andersen, L. (2008), *Efficient simulation of the Heston stochastic volatility model*, Journal of Computational Finance 11(3). In Python, `PyHeston(..., scheme="qe")` selects it.

### Heston stochastic-local volatility

The Heston model under a leverage function $L(t, S)$ and a mixing fraction $\eta$: $dS_t = \mu S_t\,dt + L(t, S_t)\sqrt{V_t}\,S_t\,dW^1_t$, $dV_t = \kappa(\theta - V_t)\,dt + \eta\sigma\sqrt{V_t}\,dW^2_t$. The leverage is an `Fn2D` of time and spot: an `Expr` reaches a device; a closure, a Python callable or a tabulated `Grid2D` — what a calibrated `LeverageSurface` converts into — keeps the process on the host. With $\eta = 1$ and $L \equiv 1$ the path is `HestonLog`'s, bit for bit. The [quant page](/docs/quant#heston-slv-leverage-calibration) calibrates $L$ to a vanilla surface.

### Correlated multi-asset GBM

`MultiGbm` simulates `k` geometric Brownian motions on one grid from a correlation matrix: the increments come from `Mcgns`, the `k`-dimensional correlated driver (independent normals through the Cholesky factor of ρ), and each asset is stepped by the exact log-Euler scheme, so the grid law is the multivariate lognormal. The output is one `(k, n)` matrix per path.

<Tabs items={['Rust', 'Python']}>
<Tab value="Rust">
<RustExample path="tests/doctest_processes_multi_gbm.rs" />
</Tab>
<Tab value="Python">
```python
import numpy as np
import stochastic_rs as srs

rho = np.array([[1.0, 0.6, -0.2], [0.6, 1.0, 0.1], [-0.2, 0.1, 1.0]])
model = srs.PyMultiGbm(mu=[0.05, 0.03, 0.01], sigma=[0.2, 0.3, 0.15], rho=rho, n=253, x0=[100.0, 50.0, 10.0], t=1.0, seed=7)
paths = model.sample_par(10_000)          # list of (3, 253) arrays
terminal = np.array([p[:, -1] for p in paths])
print(np.corrcoef(np.log(terminal).T))    # ≈ rho
```

### Wishart process (stochastic covariance)

`Wishart` simulates the matrix-valued diffusion `dX = (α aᵀa + bX + Xbᵀ) dt + √X dW a + aᵀ dWᵀ √X` on the positive semidefinite cone: the matrix CIR behind the Gouriéroux–Sufana and Da Fonseca–Grasselli–Tebaldi stochastic-covariance models. Every grid step is sampled **exactly** with the Ahdida–Alfonsi (2013) splitting (one noncentral χ² and `r` Gaussians per coordinate after an extended Cholesky of the remaining block), so any degree `α ≥ d − 1` is admissible and the paths never leave the cone. The closed-form mean and Laplace transform are available for validation. Each path is one `(n, d, d)` array.

<Tabs items={['Rust', 'Python']}>
<Tab value="Rust">
<RustExample path="tests/doctest_processes_wishart.rs" />
</Tab>
<Tab value="Python">
```python
import numpy as np
import stochastic_rs as srs

b = np.array([[-0.5, 0.1], [0.05, -0.3]])
a = np.array([[0.3, 0.1], [0.0, 0.2]])
x0 = np.array([[1.0, 0.2], [0.2, 0.5]])
process = srs.PyWishart(alpha=2.5, b=b, a=a, x0=x0, n=5, t=1.0, seed=7)
paths = process.sample_par(10_000)                    # list of (5, 2, 2) arrays

v = -0.4 * np.array([[1.0, 0.3], [0.3, 1.0]])

```

### Cheyette quasi-Gaussian short rate

`Cheyette` is the one-factor quasi-Gaussian HJM model: the state `(x, y)` follows `dx = (y − κx) dt + σ(t, x) dW`, `dy = (σ² − 2κy) dt`, and the whole forward curve is a function of that pair — `f_t(T) = f_0(T) + e^{−κ(T−t)} (x_t + G y_t)` and `P_t(T) = P_0(T)/P_0(t) · exp(−G x_t − ½ G² y_t)` with `G = (1 − e^{−κ(T−t)})/κ`. A constant `σ` is Hull–White; a displaced or CEV `σ(t, x)` adds the rate skew (Andersen–Piterbarg Vol. II, Ch. 13). The path output is the pair `[x, y]`; `short_rate`, `forward_rate` and `zero_bond` rebuild rates and bonds from it.

<Tabs items={['Rust', 'Python']}>
<Tab value="Rust">
<RustExample path="tests/doctest_processes_cheyette.rs" />
</Tab>
<Tab value="Python">
```python
import numpy as np
import stochastic_rs as srs

model = srs.PyCheyette(f0=lambda t: 0.03, kappa=0.5, sigma=lambda t, x: 0.01 + 0.3 * x, n=101, t=1.0, seed=7)
x, y = model.sample()                          # one state path (x_t, y_t), both length 101
xs, ys = model.sample_par(2000)                # (2000, 101) each
print(model.short_rate(1.0, xs[:, -1].mean()))  # ≈ 0.03: x is centred
print(model.zero_bond(1.0, 3.0, 0.0, 0.0))      # P_0(3) / P_0(1) at the zero state
```

## Common patterns

### Construction

Every process follows the same `new(args…, seed)` pattern — the model parameters first, then `n`, `x0`, `t`, and the seed source **last**, a value implementing [`SeedExt`](/docs/concepts/seeding). `Gbm` stands in for any process below:

```rust
use stochastic_rs::simd_rng::Deterministic;
use stochastic_rs::simd_rng::Unseeded;
use stochastic_rs::stochastic::diffusion::gbm::Gbm;

// auto-seeded
let p = Gbm::<f64, _>::new(0.05, 0.2, 1_000, 100.0, Some(1.0), Unseeded);

// reproducible
let p = Gbm::<f64, _>::new(
  0.05,
  0.2,
  1_000,
  100.0,
  Some(1.0),
  Deterministic::new(42),
);
```

Use `Deterministic` in tests so they replay bit-exactly, and give each process its own `Deterministic::new(seed)`: a clone of a `Deterministic` is a snapshot, so processes built from clones of one source draw identical paths. `SeedExt::reseed(u64)` resets a `Deterministic` source in place to sweep seeds without rebuilding the process.

### Sampling

Continuing with `p` from above. `sample` / `sample_par` are `ProcessExt` methods, so the trait has to be in scope:

```rust
use stochastic_rs::traits::ProcessExt;

let path = p.sample(); // Array1<f64>, length n
let paths = p.sample_par(64); // Vec<Array1<f64>>, 64 paths of length n
```

`sample_par(m)` runs on Rayon. With a `Deterministic` seed its output is bit-identical for any thread count (see [determinism](/docs/concepts/process-ext#parallel-sampling-and-determinism)).

### Acceleration

The CPU path uses SIMD (`f32x8` / `f64x8`). Every process also takes a sampling **backend** at compile time with `.on::<B>()`; `Cuda` only exists when the `cuda` feature is compiled:

```rust
use stochastic_rs::simd_rng::Unseeded;
use stochastic_rs::stochastic::device::Cuda;
use stochastic_rs::stochastic::noise::fgn::Fgn;
use stochastic_rs::traits::ProcessExt;

let fgn = Fgn::<f32, _>::new(0.7, 65_536, None, Unseeded);
let path = fgn.on::<Cuda>().sample(); // FFT on the GPU
```

Backends: `Cpu` (default), `Cuda` (`cuda`), `Metal` (`metal`), `Accelerate` (`accelerate`); each handle exists only when its feature is compiled, so an unavailable backend is a compile error. See [Backends](/docs/concepts/backends) and the [Feature flags](/docs/concepts/feature-flags) matrix.

## Euler engine

The sampling backend is a **type parameter of every process** (`Name<T, S, B = Cpu>`, switched with `.on::<B>()`), and the Euler engine is the device capability behind 127 of the 129: `gbm.on::<Metal>().sample_par(m)` samples through `ProcessExt` as usual. On `Cpu` (and `Accelerate`) that is the process's own sampler — GBM keeps its exact log-normal scheme, OU and CIR their SIMD steppers. The GPU back-ends run one device thread per path with the whole Euler–Maruyama recursion in the kernel and Philox Box–Muller normals (`sample_par` is one launch for all `m` paths):

| Backend | Feature | Device | Precision |
|---|---|---|---|
| `Cuda` | `cuda` | NVIDIA, cudarc + NVRTC | `f32` or `f64`, after `T` |
| `Metal` | `metal` | Apple Silicon GPUs, metal-oxide kernels | `f32` |

The device seed is drawn from the process's own seed source (the same `Deterministic` seed value gives the same paths, consecutive calls advance the stream, `Unseeded` draws fresh entropy). The device kernels and the fGN and sheet pipelines share one generator, Philox-4x32-10 keyed on the whole seed, so the Euler engine's back-ends agree with each other seed for seed up to libm rounding (the pipelines' back-ends draw the same normal at a cell but cut their rows from the transforms differently); the host path is the process's own stream, so CPU and device paths agree in distribution rather than bit for bit. Every process answers `device_ready()` for the configuration it holds — a `false` samples on the host, bit-identically to the `Cpu` build. [GPU support](/docs/concepts/gpu-support) tabulates what runs where.

## Generic SDE solver

`Sde` integrates a user-supplied $d$-dimensional Itô SDE $dX_t = a(X_t, t)\,dt + b(X_t, t)\,dW_t$ from a drift closure and a diffusion-matrix closure, with Euler–Maruyama, Milstein, SRK2 or SRK4 (`SdeMethod`), under Brownian or fractional noise (`NoiseModel`). It is not a `ProcessExt` implementor: `solve` returns all paths as an `Array3<T>` of shape `[n_paths, steps + 1, dim]`. `.on::<B>()` re-types it; under `NoiseModel::Fractional` the fGN increments come from `Fgn::on::<B>()`, while the integration loop and Gaussian noise run on the host. It has no Python class.

```rust
use stochastic_rs::ndarray::{array, Array1, Array2};
use stochastic_rs::simd_rng::Deterministic;
use stochastic_rs::stochastic::sde::{NoiseModel, Sde, SdeMethod};

// dS = mu S dt + sigma S dW
let (mu, sigma) = (0.05_f64, 0.2_f64);
let sde = Sde::new(
  move |x: &Array1<f64>, _t: f64| array![mu * x[0]],
  move |x: &Array1<f64>, _t: f64| Array2::from_elem((1, 1), sigma * x[0]),
  NoiseModel::Gaussian,
  None,
);
let paths = sde.solve(&array![100.0], 0.0, 1.0, 1000, 100, SdeMethod::Milstein, &Deterministic::new(42)); // [100, 1001, 1]
```

Reach for `Sde` when the equation is not one of the built-in processes, or to compare schemes on one equation; a built-in model has its own sampler and its place in the pricing stack. Every scheme takes one Brownian increment $\Delta W_n \sim \mathcal N(0, \Delta t)$ per step, and under `NoiseModel::Fractional` the field `hursts` holds one Hurst exponent $H \in (0, 1)$ per dimension.

| `SdeMethod` | Strong order | Weak order |
|---|---|---|
| `Euler` (Euler–Maruyama) | 0.5 | 1.0 |
| `Milstein` | 1.0 | 1.0 |
| `SRK2` (stochastic midpoint) | 0.5 | |
| `SRK4` (RK4 structure) | 0.5 | |

**Euler–Maruyama** (Maruyama, 1955):

$$
X_{n+1}^i = X_n^i + a^i(X_n, t_n)\,\Delta t + \sum_{j=1}^{d} b^{ij}(X_n, t_n)\,\Delta W_n^j .
$$

**Milstein** (Milstein, 1974) adds the first Itô–Taylor correction,

$$
X_{n+1}^i = X_n^i + a^i \Delta t + \sum_j b^{ij} \Delta W^j
  + \sum_{j_1=1}^{d} \sum_{j_2=1}^{d} \mathcal{L}^{j_1} b^{i,j_2}\, I_{(j_1,j_2)},
\qquad
\mathcal{L}^{j_1} b^{i,j_2} = \sum_{k=1}^{d} b^{k,j_1}\,\frac{\partial b^{i,j_2}}{\partial x_k},
$$

with the double Itô integrals taken under the commutative-noise assumption,

$$
I_{(j,j)} = \tfrac{1}{2}\bigl((\Delta W^j)^2 - \Delta t\bigr), \qquad
I_{(j_1,j_2)} \approx \tfrac{1}{2}\,\Delta W^{j_1}\,\Delta W^{j_2} \quad (j_1 \neq j_2).
$$

The off-diagonal approximation holds only when $\mathcal{L}^{j_1} b^{i,j_2} = \mathcal{L}^{j_2} b^{i,j_1}$; otherwise the Lévy area has to be simulated, which `Sde` does not do. The partial derivatives are forward finite differences with step $\varepsilon = 10^{-7}$.

**Stochastic midpoint** (`SRK2`) evaluates both coefficients at an intermediate point:

$$
\hat{X} = X_n + \tfrac{1}{2}\,a(X_n, t_n)\,\Delta t + \tfrac{1}{2}\,b(X_n, t_n)\,\Delta W_n, \qquad
X_{n+1} = X_n + a\bigl(\hat{X}, t_n + \tfrac{\Delta t}{2}\bigr)\,\Delta t + b\bigl(\hat{X}, t_n + \tfrac{\Delta t}{2}\bigr)\,\Delta W_n .
$$

**RK4 structure** (`SRK4`) averages four stages, at $t_n$, $t_n + \Delta t/2$ twice and $t_n + \Delta t$, with the weights $(1, 2, 2, 1)/6$ for the drift and the diffusion alike:

$$
X_{n+1} = X_n + \bar{a}\,\Delta t + \sum_j \bar{b}^{ij}\,\Delta W^j, \qquad
\bar{a} = \tfrac{1}{6}(a_1 + 2a_2 + 2a_3 + a_4), \quad
\bar{b}^{ij} = \tfrac{1}{6}\bigl(b_1^{ij} + 2b_2^{ij} + 2b_3^{ij} + b_4^{ij}\bigr).
$$

It is a heuristic: with one Brownian increment per step its strong order is 0.5, not 4. It helps where the drift dominates or the noise is small; for schemes of higher stochastic order see Rößler (2010) or Burrage & Platen (1994).

References: Maruyama, G. (1955), *Continuous Markov processes and stochastic equations*, Rendiconti del Circolo Matematico di Palermo 4, 48–90; Milstein, G. N. (1974), *Approximate integration of stochastic differential equations*, Theory of Probability & Its Applications 19(3), 557–562.

## Volterra (stochastic Volterra equations)

Solved by Markovian lift at `O(n N')` rather than the naive `O(n^2)` convolution. See `stochastic_rs::stochastic::volterra`.

| Type | What it is |
|---|---|
| `VolterraSde` | The general equation `X_t = X_0 + ∫ K(t-s) b(s,X_s) ds + ∫ K(t-s) σ(s,X_s) dW_s` |
| `VolterraSquareRoot` | The Volterra Heston variance leg, nonnegative by construction |
| `GaussianPolynomialVolatility` | Volatility as a polynomial of a Gaussian Volterra process, incl. the quintic parameterisation |
| `Volterra` | The Gaussian process `∫ K(t,s) dW_s` under an fBM, power-law or exponential kernel, by Markov lift for an fBM with `H < 1/2` and by the direct convolution otherwise |

Kernels implementing `VolterraKernel`: `RlKernel` (Riemann–Liouville), `ExponentialKernel` (exact at one mode), `GammaKernel`, `SumOfExponentials`.

A weakly singular kernel makes $X$ neither Markov nor a semimartingale, so every step of the direct convolution needs the whole path. Writing $K(t) \approx \sum_{l=1}^{N'} w_l e^{-x_l t}$ turns the equation into $N' \ll n$ coupled Ornstein–Uhlenbeck-like factors, each updated from its own previous value. A `VolterraKernel` supplies the nodes and weights and two closed forms the sum cannot give for the current step, which has no history yet: $K(\delta t)$ and $\int_0^{\delta t} K(u)\,du$. `VolterraLift` is the stepper, `VolterraSde` the process built on it, and `rough::MarkovLift` the same lift for `RlKernel` and coefficients of the state alone. `volterra::reference::reference_path` is the direct $O(n^2)$ discretisation with the exact kernel: the cross-implementation oracle of the lift, and the sampler `Volterra` uses for a kernel the lift cannot represent, such as an fBM kernel with $H \ge 1/2$.

### Convergence

The rates of ordinary SDE schemes do not carry over. For weakly singular kernels the strong rate is $\min\{1-\alpha,\ \tfrac12-\beta\}$ for the $\theta$-Euler–Maruyama scheme and $\min\{1-\alpha,\ 1-2\beta\}$ for Milstein (Li, Huang & Hu, 2020, arXiv:2004.04916), not $1/2$ and $1$; Liu, Hu & Gao (2024, arXiv:2412.11126) show that the Milstein rate $n^{-2H}$ is optimal. `VolterraSde` evaluates its coefficients explicitly at the left point, which puts it in the Euler–Maruyama class; these rates are the literature's and are not measured for this implementation. The kernel approximation is a second, separate error: Bayer & Breneis prove superpolynomial strong convergence in $N'$ for Lipschitz coefficients (2021, arXiv:2108.05048) and that the weak error is governed by the $L^1$ error of the kernel (2023, arXiv:2309.07023).

### An $L^1$ weight refit

A quadrature fit such as `RlKernel`'s Gauss–Laguerre rule targets a pointwise criterion, the right one for pathwise error. `volterra::fit::fit_l1` keeps the nodes and refits the weights in $L^1$ by iteratively reweighted least squares on a log-spaced grid, the objective that bounds the weak (pricing) error; `l1_error` measures the result. Use the quadrature fit for pathwise work and the refit for pricing. Measured at degree 40 on $[10^{-4}, 1]$:

| $H$ | $L^1$ error, before → after | worst pointwise relative error, before → after |
|---|---|---|
| 0.05 | 2.98e-2 → 1.29e-2 (2.31×) | 8.30e-1 → 7.14e-1 (0.86×) |
| 0.10 | 2.10e-2 → 9.02e-3 (2.33×) | 7.91e-1 → 6.69e-1 (0.85×) |
| 0.30 | 3.83e-3 → 1.35e-3 (2.83×) | 5.31e-1 → 4.19e-1 (0.79×) |
| 0.45 | 4.16e-4 → 1.14e-4 (3.64×) | 1.68e-1 → 1.17e-1 (0.70×) |

The refit can still be worse at a single $t$ (at $t = 10^{-2}$ the quadrature fit is the tighter one), and it cannot repair badly placed nodes. Near the singularity neither fit is accurate: at $t = 10^{-4}$ with $H = 0.05$ both are about 80% off, because no degree-40 exponential sum tracks $t^{H-1/2}$ that close to the origin. That is why the lift takes the first step from the closed-form boundary term and not from the sum.

### The square-root process

`VolterraSquareRoot` is the variance leg of the Volterra Heston model (Abi Jaber & El Euch, arXiv:1803.00477), and of rough Heston under the Riemann–Liouville kernel. $\sqrt{V}$ is not Lipschitz at the origin, and a naive step of the lifted system drives $V$ negative whenever the Feller condition fails. The process uses full truncation (Lord, Koekkoek & van Dijk, 2010, Quantitative Finance 10(2)): both coefficients are evaluated at $V^+ = \max(V, 0)$ and the reported path is floored. The output is nonnegative at any parameters, and the scheme is biased, not exact in law.

Three constructions in the literature keep the law and are not implemented: the state space of the multifactor approximation as a linear image of the nonnegative orthant (Abi Jaber, Bayer & Breneis, 2024, arXiv:2412.17526); simulating the integrated process first, exact in two regimes for the classical square-root process (Abi Jaber, 2024, arXiv:2412.11264); and iVi, its Volterra generalisation, which proves weak convergence with few steps and not exactness (Abi Jaber & Attal, 2025, arXiv:2504.19885). A path that touches zero is not a defect of the scheme: Friesen, Gerhold & Wiedermann (2026, arXiv:2606.07290) give a time-dependent Feller condition and show that rough kernels can attain the boundary.

`GaussianPolynomialVolatility` is the volatility $\sigma_t = p(X_t)$ alone, without the price leg; over an `ExponentialKernel` the driver $X$ is an exact Ornstein–Uhlenbeck process, the setting of the quintic model (Abi Jaber, Illand & Li, 2022, arXiv:2212.08297 and arXiv:2212.10917).

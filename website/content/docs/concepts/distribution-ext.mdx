Closed-form analytics for every distribution that has them.

`DistributionExt` is `f64`-only (not generic over `T`), and every method
returns `Option` and defaults to `None` — a distribution overrides only the
methods it has a closed form for:

```rust
// Every method is provided and defaults to None; a law overrides the ones it has a closed form for.
pub trait DistributionExt {
  fn characteristic_function(&self, t: f64) -> Option<Complex64>;
  fn pdf(&self, x: f64) -> Option<f64>;
  fn cdf(&self, x: f64) -> Option<f64>;
  fn quantile(&self, p: f64) -> Option<f64>;
  fn mean(&self) -> Option<f64>;
  fn median(&self) -> Option<f64>;
  fn mode(&self) -> Option<f64>;
  fn variance(&self) -> Option<f64>;
  fn skewness(&self) -> Option<f64>;
  fn kurtosis(&self) -> Option<f64>;
  fn entropy(&self) -> Option<f64>;
  fn moment_generating_function(&self, t: f64) -> Option<f64>;
}
```

## Coverage

**32 of the 36** distribution types implement `DistributionExt`. The four
that do not are `SimdDirichlet` and `SimdWishart` (vector- and
matrix-valued draws, with their own inherent `pdf` / `log_pdf`),
`SimdNonCentralChiSquared` (its noncentrality is supplied per draw; it backs
the exact CIR transition density) and `ComplexDistribution` (a composition
utility that pairs two distributions as the parts of a complex draw).

Implementing the trait does not mean every method has a closed form:
`SimdGed`, `SimdSkellam` and the four `truncated` wrappers answer `pdf`/`cdf`
only, nine types (`SimdAlphaStable`, `SimdBeta`, `SimdHypergeometric`,
`SimdInverseGauss`, `SimdNormalInverseGauss`, `SimdVarianceGamma`, `SimdGig`,
`SimdGeneralizedHyperbolic`, `SimdTemperedStable`) answer `None` on specific
methods; `stochastic-rs-distributions/tests/distribution_ext_coverage.rs` is
the exact matrix.

## A missing closed form is None, never zero

Project rule: a quantity the law has no closed form for is `None`, never a
silent `0.0` — a v1.x bug where a zero kurtosis made a calibration converge
on garbage is why; the previous `unimplemented!()` panic became the `Option`
in 3.0 so a generic consumer can test instead of catching a panic.

If you hit such a `None`, you have two options:

1. Use a different distribution if the moment is non-essential.
2. Open an issue / PR — the `feedback_implementation.md` rule says
   we follow papers exactly, so closed forms get added with a citation.

## Why no `statrs::distribution::*`

The library deliberately writes closed forms from scratch in
`stochastic-rs-distributions`, never delegating to `statrs`. Reasons:

1. **Generic precision**. `statrs` is `f64`-only. We need `f32`
   support for GPU + memory-bound bulk sampling.
2. **No-allocation guarantees**. `statrs` allocates in some cdfs; the
   bulk samplers in this library cannot afford that.
3. **Audit trail**. Every formula in this crate is anchored to a paper
   citation, with a comparison test against the paper's numerical
   tables. `statrs`'s implementations are competent but lack that
   audit trail.

See the per-distribution pages under
[Distributions](/docs/distributions) for the formulas, tests, and
references.

## Generic over float where it simulates

Processes, distribution samplers and Monte Carlo code are generic over `T: FloatExt`, implemented by `f32` and `f64`: `f32` halves the memory traffic and is the only precision Apple GPUs have. Closed-form analytics — `DistributionExt`, `ModelPricer`, `Greeks` — work in `f64`, and analytic code bounded on `RealExt` also accepts a custom scalar such as an AAD dual number (see [traits](/docs/concepts/traits#realext-simdfloatext-floatext)).

## Paper-anchored implementations

Every model and algorithm cites its paper in the source file:

```rust
//! Reference: Heston (1993). DOI: 10.1093/rfs/6.2.327
```

The implementation follows the paper's formulas, without simplifications; where a formula is numerically unstable, it follows a cited correction instead of an unpublished rewrite. Comparison tests check implementations against the papers' numerical examples.

## `ndarray` in and out

Numerical arrays in the API are `ndarray` types (`Array1<T>`, `Array2<T>`, views), re-exported as `stochastic_rs::ndarray`.

## Error convention

One rule for every crate, from the distributions up to the calibrators:

- **Invalid parameter → panic, naming the parameter and its value.** A negative volatility, a Hurst exponent outside `[0, 1]`, a grid with fewer than two points: programmer errors, not runtime states, so constructors, setters and the functions that take model parameters `assert!` them with a message of the form ``sigma must satisfy `sigma > 0.0`, got sigma = -0.2``. Never a silent clamp, a silent zero or a silent `None`. A copula's `theta` is checked where it is used instead: `set_theta` stores any value, and `check_theta` and the `Result`-returning methods that read it (`sample`, `pdf`, `cdf`, …) return `CopulaError::InvalidParameter` for a `theta` outside the family's interval.
- **Not computable at this point → `NaN`, documented.** A price outside a model's domain, a Greek at an expired option, an implied volatility with no root: legitimate states, returned as `f64::NAN` from methods whose docs say when. A function that must compute a number never returns 0 in its place; a closed form a law does not have is `None` (`DistributionExt`), not a sentinel. A *query* argument outside the domain — a non-positive strike, a maturity of zero — is this case too; only a broken precondition on a model parameter or an empty input panics.
- **Data-dependent failure → `Result::Err`.** A calibration produced no result, a correlation matrix estimated from data is not positive-definite, a fit rejected its input, a vine could not be built from the supplied pairs: the caller needs a graceful path, so `Calibrator::calibrate`, the copula `fit` / `new_with_corr` / vine constructors and the estimators return `Result` (`anyhow::Error` in quant, `CopulaError` in copulas); a calibration that ran but did not converge is `Ok` with `converged() == false`. `Calibrator::Error` is bounded `Debug + Display + Send + Sync + 'static`.
- **Environmental failure on a device → probe first, then `Result` or a panic that says so.** No GPU behind a marker, a runtime that will not start, a kernel that will not compile, an allocation that fails: `handle.probe()` reports it as a `DeviceError` before any sampling, and the `try_sample` / `try_sample_par` calls return the same error at sampling time. The plain `sample*` calls panic with that error's message, so a device failure is never a silent host fallback.

## What is stable and what may grow

Enums that catalogue an open set — copula families, day-count and holiday conventions, interpolation and finite-difference schemes, loss metrics, error kinds — are `#[non_exhaustive]`, so a new family or scheme is not a breaking change; match them with a wildcard arm. Enums that are closed by definition (`OptionType`, `OptionStyle`, `Moneyness`, the payer/receiver and up/down × in/out kinds) stay exhaustive. Processes and pricers with public fields are built through `new` and the `with_*` setters; a struct literal is not a supported construction (a public-field process also carries its backend handle, `backend: Cpu`), so adding a field is not a breaking change for code that uses the constructors.

## Non-goals

- **Not a general-purpose SDE / PDE solver.** The Monte Carlo toolkit (antithetic, control variate, stratified, importance sampling, quasi-MC, MLMC) and the PDE pricers serve quant-finance models.
- **Not a scipy.stats clone.** The distributions and estimators are the ones quant-finance workflows need; a law without such a use case is out of scope.
- **Not a full production pricing stack.** The vol-surface pipeline, calibrators and risk metrics target liquid equity vanilla and lightly exotic products; fixed-income, credit and OTC-commodity deployments will likely need their own layer on top (see [Comparison](/docs/comparison)).

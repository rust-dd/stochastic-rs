```rust
use stochastic_rs::prelude::*;
```

Brings **27 items in 6 groups**. The lists below are name groupings; [Importing concrete types](#importing-concrete-types) has a runnable example.

## Trait core (9)

```
RealExt, FloatExt, SimdFloatExt,
ProcessExt, BivariateExt, MultivariateExt,
DistributionExt, DistributionSampler,
TimeExt
```

These are the bounds you write on generic functions. Code that simulates carries `T: FloatExt` (the full SIMD + RNG surface, so `f32`/`f64` only); analytic pricing code carries the looser `T: RealExt` (scalar arithmetic only), which a custom scalar such as an AAD dual number can implement.

## Pricing (1)

```
ModelPricer
```

[`ModelPricer`](/docs/concepts/model-pricer) is the concrete-typed pricing surface (no `&dyn`). A pricer's Greeks are an inherent `greeks(s, k, r, q, tau, option_type)` method, not a prelude trait.

## Calibration (3)

```
Calibrator, CalibrationResult, ToModel
```

`ToModel` turns a calibration result into a concrete pricer through an associated type.

## Option types (3)

```
Moneyness, OptionStyle, OptionType
```

`Moneyness` (deep ITM / ITM / ATM / OTM / deep OTM), `OptionStyle` (European / American), `OptionType` (Call / Put).

## Backend / sampling (6)

```
Backend, Cpu,
VolterraKernel,
Seeded, SimdDistribution, SimdKernel
```

`Backend` is the device marker behind every process's `.on::<B>()`; `Cpu` is its default (zero-sized) implementor, and the other backends (`Cuda`, `Metal`, `Accelerate`) are feature-gated and live in `stochastic_rs::stochastic::device`. `VolterraKernel` is the nodes/weights/evaluate trait behind the Markovian-lift rough processes (`RlKernel`, `ExponentialKernel`, `GammaKernel`, `SumOfExponentials`). `SimdDistribution` makes `.seeded(&seed)` resolve on a stateless law such as `SimdNormal`, binding it to a `Seeded` stream whose draws take `&mut self`; `SimdKernel` adds `fill_with(&mut rng, out)`, a bulk fill driven by any `rand` rng.

## Estimation (5)

```
HurstEstimator, FractalDimEstimator,
HypothesisTest, DiffusionModel,
TailDependence
```

Without these in scope an `.estimate()` call does not compile. `HurstEstimator` covers the eight Hurst estimators, `FractalDimEstimator` the fractal-dimension family, `HypothesisTest` the sixteen test-result types (stationarity, structural break, random walk, functional form, normality, goodness of fit — Kolmogorov-Smirnov, chi-square, the copula `GofResult` — and autocorrelation), `DiffusionModel` the parametric-SDE estimators, and `TailDependence` the upper/lower tail coefficients of bivariate copulas.

## What is *not* in the prelude

All of these are reachable through `stochastic_rs::traits::*`:

- `ShortRatePricer` / `ToShortRateModel` — the short-rate family. Its query is a yield curve and a drift offset rather than a spot and a strike, so it answers a different question from `ModelPricer`. `ToShortRateModel` builds the lattice model from a short-rate calibration result alone.
- `VanillaEuropeanCall` — a marker you implement: it asserts a `ModelPricer` really is a European vanilla call so `vol_surface` can invert it.
- `GreeksExt` — implemented only by the two Monte Carlo Malliavin estimators; the analytic pricers expose Greeks through an inherent method.
- `FgnBackend`, `SheetBackend`, `EulerBackend`, `HostBackend` — the capability subtraits of `Backend`, named only in generic code over backends.
- `Instrument` / `InstrumentExt` / `PricingEngine` / `PricingResult` — a cross-engine comparison harness: two instruments and two engines for validating models against each other on the same contract. The crate's two pricing layers are `ModelPricer` (spot/strike query) and the instruments' `.valuation(curve)`.

The prelude needs no feature flag: `use stochastic_rs::prelude::*;` works on every supported feature combination.

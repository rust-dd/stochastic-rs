# `PricerExt` and `ModelPricer`

Two related but distinct surfaces. Both are plain `f64` traits — neither
is generic over `T: FloatExt`.

## `PricerExt`

Date-aware pricing surface (it extends `TimeExt`). Every concrete pricer
implements:

```rust
pub trait PricerExt: TimeExt {
    fn calculate_call_put(&self) -> (f64, f64);
    fn calculate_price(&self) -> f64;
    fn implied_volatility(&self, c_price: f64, option_type: OptionType) -> f64 {
        f64::NAN // default: not every pricer inverts a price to a vol
    }
}
```

The option type, strike, spot, and maturity all live on the pricer
struct itself (set at construction, e.g. via a `HestonPricer::builder(...)`)
rather than being passed to `calculate_price`. `BSMPricer` used to be the
other example here; it has since moved to `ModelPricer` below, where the
query is an argument.
`calculate_call_put` returns both legs regardless of the pricer's own
`option_type`; `calculate_price` returns the one `option_type` was built
with. `TimeExt::tau_or_from_dates` derives $\tau$ from either an explicit
`tau` or an `(eval, expiration)` pair with a day-count convention.

## `ModelPricer`

Prices a strike/tau grid directly, no `&dyn`, no `Box<dyn>`:

```rust
pub trait ModelPricer {
    fn price_call(&self, s: f64, k: f64, r: f64, q: f64, tau: f64) -> f64;

    // default: put-call parity from price_call
    fn price_put(&self, s: f64, k: f64, r: f64, q: f64, tau: f64) -> f64 {
        let call = self.price_call(s, k, r, q, tau);
        call - s * (-q * tau).exp() + k * (-r * tau).exp()
    }

    // default: dispatches to price_call / price_put
    fn price_option(&self, s: f64, k: f64, r: f64, q: f64, tau: f64, option_type: OptionType) -> f64 {
        match option_type {
            OptionType::Call => self.price_call(s, k, r, q, tau),
            OptionType::Put => self.price_put(s, k, r, q, tau),
        }
    }
}
```

Unlike `PricerExt`, nothing about the contract (strike, spot, tau) is
baked into the pricer — every price query passes its own `(s, k, r, q,
tau)`, which is what makes vectorized pricing across a strike/maturity
grid (vol-surface construction, calibration) cheap: one model instance,
many `price_option` calls.

## Why two traits

`PricerExt` is the user-facing API for one-off pricing of a specific
contract. `ModelPricer` is the building block for vol surfaces and
calibrators, where you price thousands of `(k, tau)` points against a
single model.

`ToModel` bridges a calibration result to the concrete `ModelPricer` it
produces:

```rust
pub trait ToModel {
    type Model: ModelPricer;
    fn to_model(&self, r: f64, q: f64) -> Self::Model;
}
```

## Greeks via `GreeksExt`

Greeks are a **separate** trait from both `PricerExt` and `ModelPricer` —
`GreeksExt` — with one required accessor (`delta`) and NaN-defaulted
accessors for the rest (`gamma`, `vega`, `theta`, `rho`, `vanna`, `charm`,
`volga`, `veta`), plus an aggregating `greeks()` that calls all nine and
packs them into a `Greeks` struct (plain `f64` fields, not generic).

Pricers that expose Greeks do so via **inherent methods**
(`BSMPricer::delta`, `HestonPricer::delta`, …); `GreeksExt` gives generic
code one dispatch point when it needs to treat several pricer types
uniformly. The default `greeks()` calls the individual accessors, which
is fine for analytical pricers but wrong for Monte Carlo pricers unless
they override it — see the
[greeks-pattern SKILL](https://github.com/dancixx/stochastic-rs/blob/main/.claude/skills/greeks-pattern/SKILL.md)
for the single-pass protocol MC pricers use instead.

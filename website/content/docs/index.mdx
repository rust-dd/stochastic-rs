stochastic-rs is an open-source quantitative-finance library for Rust and Python. Simulate **132 stochastic processes**, price and calibrate against them, and move any of it to a GPU by naming one. The model and its law stay the same on the device; a configuration the kernels cannot carry samples on the host, and `device_fallback()` says why.

## One thread, end to end

Simulate a batch, move it to a GPU, price the model in closed form, and estimate a parameter from a path.

**Sample a batch.** Every process is built the same way — parameters, grid, horizon, seed — and every one has `sample`, `sample_par` and a mapped form.

<Tabs items={['Rust', 'Python']}>
<Tab value="Rust">

```rust
use stochastic_rs::prelude::*;
use stochastic_rs::simd_rng::Deterministic;
use stochastic_rs::stochastic::diffusion::gbm::Gbm;

let gbm = Gbm::<f32, _>::new(0.05, 0.2, 1_024, Some(100.0), Some(1.0), Deterministic::new(7));
let paths = gbm.sample_par(1_000);   // 1 000 paths of 1 024 points
```

</Tab>
<Tab value="Python">

```python
import stochastic_rs as srs

gbm = srs.PyGbm(0.05, 0.2, 1024, x0=100.0, t=1.0, seed=7)
paths = gbm.sample_par(1_000)        # a (1000, 1024) numpy array
```

</Tab>
</Tabs>

**Move it to a GPU.** `.on::<Metal>()` — or `device="cuda"` from Python — is the only change. `sample_map_view` reads each row where the kernel wrote it instead of copying the batch out first.

<Tabs items={['Rust', 'Python']}>
<Tab value="Rust">

```rust
use stochastic_rs::stochastic::device::Metal;

let terminal: Vec<f32> = gbm.on::<Metal>().sample_map_view(200_000, |p| p[p.len() - 1]);
```

</Tab>
<Tab value="Python">

```python
gbm = srs.PyGbm(0.05, 0.2, 1024, x0=100.0, t=1.0, seed=7, device="cuda", dtype="f32")
terminal = gbm.sample_par(200_000)[:, -1]
```

</Tab>
</Tabs>

<Callout>
The host and the device draw different random streams, so no path is shared, but the *law* is, and a test suite compares the two on every process the engine serves. [What that means exactly →](/docs/concepts/gpu-support)
</Callout>

**Price the same model in closed form.** A pricer holds model parameters and takes the query as arguments, so one instance prices a whole strike-maturity grid.

```rust
use stochastic_rs::quant::pricing::heston::HestonPricer;

let model = HestonPricer::new(0.04, -0.7, 2.0, 0.04, 0.3, None);
let call = model.price_call(100.0, 100.0, 0.05, 0.02, 0.75);   // 7.7311
```

**Read a parameter back out.** The estimators take a path and return the parameter that generated it, with diagnostics.

```rust
use stochastic_rs::stats::hurst::rs::RescaledRange;
use stochastic_rs::stochastic::process::fbm::Fbm;

let fbm = Fbm::<f64, _>::new(0.7, 4_096, Some(1.0), Deterministic::new(11)).sample();
let h = RescaledRange::default().estimate(fbm.view())?;         // 0.61 for a true 0.7
```

## What are you here for?

**To simulate.** 132 processes behind one trait — diffusions, jumps, stochastic volatility, short rates, fractional and rough, point processes, subordinators, conditional-variance time series: Heston and its rough relatives, Bates, SABR, CGMY, Hull-White, LMM, fBm. → [Processes](/docs/processes) · [Tutorials](/docs/tutorials)

**To price or calibrate.** Analytic, Fourier, ADI and Monte Carlo pricers with first- and second-order Greeks; fifteen calibrators behind one `Calibrator` trait; SVI and SSVI surfaces; curves, bonds, credit and risk. → [Quant](/docs/quant)

**To estimate.** Eight Hurst estimators, realised measures, jump tests, cointegration, changepoints, extreme value, GARCH fitting — each with the paper it came from. → [Stats](/docs/stats)

**To draw.** 35 SIMD distribution samplers, most with closed-form characteristic function, pdf, cdf and moments, and 23 copulas with fitting and goodness-of-fit. → [Distributions](/docs/distributions) · [Copulas](/docs/copulas)

**To do it from Python.** 308 classes and functions, NumPy in and NumPy out, and the same `device=` argument. → [Python](/docs/python)
